### GATE-04 の詳細

指示書テンプレ v1.7 の Step 1.5 Phase A（着地パス動的特定）L294 に、未クオートのコマンド置換による空白ワード分割バグが存在する。

```
for subdir in $(ls -dt "$DL_DIR"/files\ \([0-9]*\)/ 2>/dev/null); do
```

コマンド置換の結果は語分割を受けるため、パス `.../files (2)/` が `.../files` と `(2)/` の2語に分割される。フォルダ名「files (N)」は必ず半角スペースを含むため、後続の `[ -f "$subdir$TARGET_FILE" ]` が永久にヒットしない。

実測結果は次のとおりである。

```
語1 = [/home/claude/t/w/files]
語2 = [(2)/]
回収結果 = （回収できず）
```

影響は次のとおりである。

- ブラウザDLが `files (N)/` サブフォルダへ着地した場合、実在するファイルを「見つかりません」と誤判定して停止する
- v1.7 が「DL着地ズレ抜本対応」として実装したフォールバック機能そのものが機能していない
- データ損失は発生しない（安全側に停止する）が、正当な実行を誤ってブロックする
- v1.7 由来で発行済みの指示書すべてに同じ欠陥がある

なお同じ L309 の `for candidate in "$DL_DIR/$TARGET_FILE" "$DL_DIR"/files\ \([0-9]*\)/"$TARGET_FILE"` はグロブ展開であり、展開結果は語分割を受けないため安全である。問題は L294 の1箇所のみである。

修正方針は `20260728_横断_指示書テンプレv1_8設計方針_追補_v1_1.md` に記載した。
