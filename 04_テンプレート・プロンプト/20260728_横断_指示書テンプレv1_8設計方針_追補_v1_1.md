## 2. 追加の根拠

### 2-1. 出典資料の記述

第3回勉強会資料 `人間の介入方法詳細.md` は次のように規定している。

> セキュリティチェックは確認コマンド（grep等）と実行結果を必ず記録する。「チェックした」宣言だけでなく実行結果が履歴に残るようにする。

### 2-2. 実際に発生した事象

2026年7月27日（月曜日）に作成した ファイル管理台帳 v2.4 において、第1章1-1 #1 のファイル名欄が v2_3 表記のまま残存した。

版上げ時の置換取り残しは、次の4箇所で多発する既知のパターンである。

1. タイトル行
2. ファイル名行
3. 版依存の運用ルール本文
4. 現在形の記述

現行運用では「生成後に旧版番号grep走査を必ず実施する」というルールが存在する。ただし**走査の実行結果を残す規定がない**ため、実施したかどうかを事後に検証できない。上記の残存はこの構造的な穴から生じている。

## 3. 追加項目1：版上げ時のgrep走査結果の記録

### 3-1. 注意事項12（新規）

本文の方針は次のとおりとする。

- 版上げを伴う編集を行った場合は、生成直後に旧版番号の全文走査を実行する
- 走査コマンドの例：`grep -n "v2_4" "$TARGET_FILE"`
- 走査対象の版番号は「直前の版番号」と「2つ前の版番号」の両方とする（連鎖コピーによる取り残しを検出するため）
- ヒット件数が0でない場合は、保存処理へ進まず該当行を修正してから再走査する
- 走査は次の4箇所を必ず含める。タイトル行、ファイル名行、版依存の運用ルール本文、現在形の記述

### 3-2. 自己チェックリスト14（新規）

チェック項目の本文は次のとおりとする。

- 旧版番号grep走査を実行し、**その標準出力を完了報告に貼付したか**
- ヒット件数が0であることを出力上で確認できるか
- 「チェック済み」という宣言のみで済ませていないか

### 3-3. 完了報告フォーマットへの追加

設計方針 v1.0 は完了報告フォーマットに環境情報（`uname -s` の結果）を追加する方針を定めている。ここに1ブロックを追加する。

```
【旧版番号走査結果】
実行コマンド: grep -n "<旧版番号>" "<対象ファイル>"
出力:
（標準出力をそのまま貼付。0件の場合はその旨を明示）
ヒット件数: 0
```

出力が空である場合も「0件」と明示的に記載する。空欄のままにしない。

## 3B. 追加項目2：Step 1.5 Phase A の空白ワード分割バグ修正

### 3B-1. 検出内容

設計方針 v1.0 は Step 1.5 Phase A を「そのまま」または「パス変数参照に置換」として扱っており、ロジックそのものの欠陥は想定していない。しかし v1.7 本体の該当行に実害のあるバグが存在する。

v1.7 L294 の記述は次のとおりである。

```
for subdir in $(ls -dt "$DL_DIR"/files\ \([0-9]*\)/ 2>/dev/null); do
    if [ -f "$subdir$TARGET_FILE" ]; then
```

コマンド置換 `$(...)` の結果は語分割を受ける。フォルダ名「files (N)」は必ず半角スペースを含むため、`.../files (2)/` が `.../files` と `(2)/` の2語に分割され、`[ -f "$subdir$TARGET_FILE" ]` が永久にヒットしない。

2026年7月28日（火曜日）の実機検証結果は次のとおりである。

```
語1 = [/home/claude/t/w/files]
語2 = [(2)/]
回収結果 = （回収できず）
```

### 3B-2. 影響範囲

| 項目 | 内容 |
|---|---|
| 症状 | `files (N)/` サブフォルダに着地したファイルを回収できず「見つかりません」と誤判定して停止する |
| 深刻度 | 中。データ損失は発生しない（安全側に停止する）が、正当な実行を誤ってブロックする |
| 皮肉な点 | v1.7 が「DL着地ズレ抜本対応」として新設したフォールバック機能そのものが機能していない |
| 波及 | v1.7 由来で発行済みの指示書すべて |
| 安全な箇所 | L309 の `for candidate in "$DL_DIR/$TARGET_FILE" "$DL_DIR"/files\ \([0-9]*\)/"$TARGET_FILE"` はグロブ展開であり、展開結果は語分割を受けないため安全である |

### 3B-3. 修正方針

コマンド置換を廃し、L309 と同じグロブ展開に統一する。グロブの展開結果は語分割を受けないため空白安全である。あわせて全候補を走査し、SHA256 が一致するものを優先採用する形にする。

```
for c in "$DL_DIR/$F" "$DL_DIR"/files\ \([0-9]*\)/"$F"; do
    [ -f "$c" ] || continue
    H=$(sha "$c")
    if [ "$H" = "$EH" ]; then FOUND="$c"; break; fi
    if [ -z "$MIS" ]; then MIS="$c"; MISH="$H"; fi
done
```

グロブ展開に変更すると `ls -dt` による更新日時の降順が失われ、辞書順になる。ただし全候補を走査して SHA256 一致を優先するため、採用結果は順序に依存しない。順序が影響するのは、一致するものが1件もない場合にどの候補のハッシュを診断として表示するかのみである。

代替案として `while IFS= read -r d; do ... done < <(ls -dt ...)` によるプロセス置換も検証済みであり、こちらは更新日時順を保持できる。ただしグロブ方式のほうが構文が単純でプロセス置換を要さないため、本追補ではグロブ方式を推奨する。

### 3B-4. 注意事項13（新規）

- パスを含むリストをループで回す場合、未クオートのコマンド置換 `for x in $(...)` を使用しない
- 半角スペースを含むパスが語分割される。特に `files (N)/` のようにスペースが構造上必ず含まれる場合、不具合が恒常化する
- 代替は次の2つとする。グロブ展開 `for x in "$DIR"/pattern` を使うか、`while IFS= read -r x; do ... done < <(cmd)` を使う
- `cmd | while read` は本体がサブシェルになり変数が親シェルへ残らないため使用しない

### 3B-5. 自己チェックリスト15（新規）

- `for` ループの対象に未クオートのコマンド置換を使っていないか
- スペースを含みうるパスを扱う箇所で、語分割の検証を行ったか
