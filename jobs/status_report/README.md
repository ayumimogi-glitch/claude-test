# status_report

実行状況の統合レポートに関するジョブを置く。

正本は マスターナレッジ の
`claude/20260916_横断_実行状況の統合レポート_運用手順書_v1_3.md` である。
記述が食い違った場合は運用手順書を優先する。

## 分担のどこにあたるか

| 段 | 担当 | 内容 |
|---|---|---|
| 1 取得 | Claude（集約タスク） | スケジュールタスクの一覧と出力先を走査し、実行状況サマリのJSONを作る |
| 2 画像化 | ChatGPT | JSONを受け取り、値を変えずに画像1枚とHTMLを作る |
| 3 検査 | このディレクトリ | 出来たHTMLが規約どおりかを機械で判定する |

3段目だけをスクリプトに固定する。見た目の良し悪しや文面の適切さは判断が要るため、ここに入れない。

上の表は目指す分担であり、現在の実態ではない。実態は次節に書く。

## write_run_result.py

各スケジュールタスクが残す実行結果JSONを作る。1段目の集約が読む入力である。

```
python3 write_run_result.py --task kousuu-shukei --environment CODE --status normal \
                            --output "Box 工数集計_自動生成" --output-count 1 \
                            --out work/run_result.json
```

キーは8つで固定する。増やさない。減らさない。status は normal、failed、aborted の
いずれかとする。normal 以外のときは needs_decision を1件以上持つ必要がある。

既にあるファイルを調べるだけの場合は `--validate <パス>` を使う。
終了コードは、合格なら 0、不合格なら 1、引数の誤りなら 2 である。

形をスクリプトに固定する理由は2つある。

- キーが増減すると集約側が壊れる。本文に書いた形をモデルが毎回組み立てると値が揺れる。
  2026/09/16 のダッシュボードの実行で、中止時の output が指示と違う値になった
- 中止と失敗のときこそ書き出す必要がある。忘れやすいのはその経路である

ファイルを作るところまでを担い、置く先への転送は担わない。CODE のコンテナから
Box と Google Drive へはコネクタ経由でしか書けず、スクリプトからは呼べないためである。
作ったファイルを呼び出し側がコネクタでアップロードする。
置き場は Google Drive の `Claude実行状況_受け渡し` フォルダとし、
ファイル名は `YYYY-MM-DD_横断_実行結果_<タスク名>.json` とする。

Mac のローカルスケジュールタスクは、このスクリプトを使わず
`jobs/inquiry_dashboard/place_to_box.py` が同じ形のJSONを Box へ直接書く。
ローカルからは Box Drive の同期フォルダへ直接書けるためである。

## verify_report.py

```
python3 verify_report.py --html 2026-09-16_横断_実行状況レポート.html \
                         --json 2026-09-16_横断_実行状況サマリ.json
```

終了コードは、すべて合格なら 0、1件以上の不合格なら 1、入力を読めなければ 2 である。

判定する項目は次のとおりである。重要度「高」は1件でも落ちたら差し替えを止める。

| 重要度 | 項目 |
|---|---|
| 高 | 角丸・影・グラデーション・光彩を使っていない |
| 高 | 丸数字・矢印記号・エムダッシュ・全角数字・置換文字を使っていない |
| 高 | 配色が palette の範囲内である（見出し帯の白文字は許容する） |
| 高 | font-family が font_stack と一致する |
| 高 | summary の4つの値（total_tasks・normal・failed_or_missing・needs_decision）が本文にある |
| 高 | 要判断の表題と3択が本文にある |
| 高 | 埋め込みJSONが元JSONと一致する |
| 中 | 書体を複数並べている |
| 中 | 制作幅が canvas.width_px と一致する |
| 中 | 対象期間の日付が本文にある |
| 中 | 失敗が0件のとき「該当なし」と書かれている |
| 中 | 成果物の置き場と注記の各行が本文にある |

判定の対象は本文だけである。埋め込みJSONの中の文字は禁止文字の判定に含めない。元データに含まれる文字で不合格になるのを避けるためである。

## この検査が生まれた経緯

2026/09/16 に作った初版のレポートで、対象期間の区切りにエムダッシュが1件使われていた。
原因は、渡したJSONの style.rules にエムダッシュの禁止を書いていなかったことである。
毎回人の目で確かめるのは続かないため、判定を機械に固定した。

見出し帯の白文字を許容するのは、palette に白が無い一方で、
標準テイストが「見出しはNEC Blueの塗りつぶし帯に白文字」と定めているためである。
