# mkp-status

現在の進捗状況を要約する。版番号は実体照合の結果のみを根拠にする。

## 発動条件

- 「進捗確認」「今の状況」などの入力
- 新規チャット開始時の状況把握
- 引き継ぎサマリ作成前の棚卸し

「今どうなってる」のような曖昧な入力の場合は、`AskUserQuestion` で「進捗確認（本コマンド）か、ブロック確認（mkp-blockers）か」を先に確認してから動作する。

## 実行手順

### Step 1: 現行版の確定

`mkp-ledger` の走査ロジックを実行し、主要な版付き正本の現行版を確定する。対象は次の4件とする。

| # | 対象 |
|---|---|
| 1 | ファイル管理台帳 |
| 2 | 採番台帳 |
| 3 | 施策ID管理 |
| 4 | ClaudeCode指示書テンプレ |

メモリ記載の版番号は参考値としてのみ扱い、実体と異なる場合は**実体を採用し、差異を明示する**。

### Step 2: HITL状態の集計

AGENT_STATE.md から状態別件数を取得する。

### Step 3: 当日の実績確認

Googleカレンダーの当日「【実績】」予定を確認する。並走分岐の防止のため、メモリと当日実績の両方を確認してから着手判断を行う。

### Step 4: 報告

次の形式で報告する。1画面に収める。

```
現行版（実体照合 YYYY/MM/DD 実行）
  ファイル管理台帳: v<X>.<Y>（<N>バイト・二拠点一致 あり/なし）
  採番台帳: v<X>.<Y>
  施策ID管理: v<X>.<Y>
  指示書テンプレ: v<X>.<Y>
  メモリとの差異: なし / あり（<詳細>）

HITL状態
  BLK <n>件 / GATE <n>件 / QRY <n>件 / REV <n>件

本日の着手候補（最大3件・優先順）
  1. <件名>（理由）
  2. <件名>（理由）
  3. <件名>（理由）
```

## 出力ルール

- 要点を先に出す。前置きを書かない
- 版番号は必ず実体照合の実行日を併記する
- 確認していない事項に「確実に」「必ず」といった断定表現を使わない
- 着手候補は3件とし、優先順位と理由を付ける

## 禁止事項

- 実体照合を省略して版番号を報告すること
- メモリの版番号のみを根拠に「現行版は v<X>.<Y> です」と断定すること
