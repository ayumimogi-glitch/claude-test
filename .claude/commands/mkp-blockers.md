# mkp-blockers

AGENT_STATE.md を読み込み、HITL状態（GATE / REV / QRY / BLK）を確認して処置候補を提示する。

## 発動条件

- 「ブロッカー確認」「詰まっているものある」などの入力
- 朝イチ対話 Step 3 の実行時
- 週次棚卸しの実行時

「今どうなってる」のような曖昧な入力の場合は、`AskUserQuestion` で「進捗確認（mkp-status）か、ブロック確認（本コマンド）か」を先に確認してから動作する。いきなり本コマンドを実行しない。

## 参照ファイル

| ファイル | 用途 |
|---|---|
| AGENT_STATE.md | HITL状態の一次ソース |
| 20260728_横断_HITL状態運用ルール_v1_0.md | 判定基準 |
| ブロッカー一元管理.md | 他者依存ブロッカーの経過日数 |

所在は OneDrive 茂木_作業中/04_テンプレート・プロンプト/ を起点とする。実パスが確定できない場合は `mkp-ledger` を先に実行する。

## 実行手順

### Step 1: 読み込み

AGENT_STATE.md を読み込み、状態別に件数を集計する。

### Step 2: 優先度判定

次の順に提示する。

| 順位 | 状態 | 理由 |
|---|---|---|
| 1 | BLK | 放置すると他タスクの前提が壊れるため |
| 2 | QRY（経過日数の長い順） | 他者依存であり待ち時間が伸びるため |
| 3 | GATE | 茂木さんが決めれば即座に進むため |
| 4 | REV | 成果物は出来ており確認だけが残っているため |

### Step 3: 提示

各行について次を1行で示す。冗長な前置きは書かない。

```
[状態] ID: 件名 / 依存先 / 解除条件
```

### Step 4: 処置の選択

`AskUserQuestion` で処置候補を選択肢として提示する。選択肢は最大4つ、1問のみとする。

処置の型は次の4種である。

| 型 | 内容 |
|---|---|
| 解除 | 解除条件が満たされたため「解除済み」へ移動する |
| 催促 | QRY の依存先へ連絡する。連絡文の下書きを生成する |
| 降格 | BLK を GATE へ、GATE を通常タスクへ落とす |
| 据え置き | 今回は動かさない。次回確認日を設定する |

### Step 5: 反映

選択された処置を AGENT_STATE.md へ書き込む。行は削除せず「解除済み」セクションへ移動する。

## 出力ルール

- 過剰な前置き・装飾的な文を書かない。要点を先に出す
- 同じ前提条件を再説明しない
- 提案が必要な場合は3案とし、優先順位と理由を付ける
- 根拠のない断定表現を使わない。確認していない事項は「未確認」と明記する

## 禁止事項

- 状態を付けずに「詰まっている」とだけ報告すること
- 根拠列を空のまま行を追加すること
- 曖昧入力に対して確認なしで本コマンドを実行すること
