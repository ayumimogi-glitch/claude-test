# mkp-ledger

版付き正本の現行版番号を、メモリや台帳の記載ではなく**実体**から確定する。

## 発動条件

以下のいずれかに該当する場合、本コマンドを実行してから作業に着手する。

- 版付き正本の版上げに着手するとき
- 「現行版はいくつか」を判断する必要があるとき
- 新規チャットで版付き文書を扱い始めるとき

## 背景（なぜ必要か）

2026年7月27日（月曜日）、メモリ記載の v2.3 を起点に v2.4 を作成したところ、保存直前に既存の v2.4 を発見し、破棄して v2.5 として再作成する手戻りが発生した。

原則は「記録より実体を優先」である。メモリの版番号は起点にしない。

## 引数

対象ファイルの基本名を受け取る。例：`ファイル管理台帳`、`採番台帳`、`施策ID管理`

## 実行手順

### Step 1: 対象ベースパスの確定

```
ONEDRIVE_BASE / BOX_BASE はOS判定で分岐させる。
Mac:     $HOME/Library/CloudStorage/OneDrive-日本電気株式会社
         $HOME/Library/CloudStorage/Box-Box/個人作業/NES販促G/茂木_マーケプロモ業務
Windows: /c/Users/mogi.ayumi/OneDrive - 日本電気株式会社
         /c/Users/mogi.ayumi/Box/個人作業/NES販促G/茂木_マーケプロモ業務
```

全パス参照はダブルクオートで囲む。Windows側パスに半角スペースが2箇所含まれるため、クオート漏れは語分割エラーになる。

### Step 2: 全走査（find -name は使用禁止）

`find -name` はNFC/NFD不一致により日本語ファイル名を取りこぼす。直接パス指定と `os.listdir` および `unicodedata.normalize("NFC")` を使用する。

走査対象は次を**すべて**含める。1箇所でも漏らすと並走分岐を見落とす。

| # | 走査先 |
|---|---|
| 1 | OneDrive 茂木_作業中/04_テンプレート・プロンプト/ 直下 |
| 2 | 同 旧版/ |
| 3 | OneDrive 茂木_作業中/02_施策別資料/共通・横断/ |
| 4 | OneDrive 茂木_作業中/一時ファイル_月末整理/ |
| 5 | Box 茂木_マーケプロモ業務 ツリーの同等サブ |
| 6 | Box 茂木_作業中 ツリーの同等サブ |
| 7 | 99_アーカイブ 配下 |

Box側に「茂木_作業中」と「茂木_マーケプロモ業務」の2ツリーが並走しており、同名フォルダに資料が分散している。両ツリーを走査しないと取りこぼす（2026年7月27日に実害が発生した）。

### Step 3: 版番号の抽出と比較

- 版選択は `re.fullmatch` で厳密化する（部分一致にしない）
- R系判定は「R直後が数字」であることを条件にする（RF01 を誤検出しない）
- 版比較は文字列ではなく `(int, int)` タプルで行う（v1_10 > v1_9 を正しく判定するため）

### Step 4: SHA256とサイズの取得

各ヒットについて SHA256 とバイトサイズを取得する。Mac は `shasum -a 256`、両環境で `sha256sum` も動作する。

### Step 5: 報告

次の形式で報告する。**件数1のアサーションを通してから断定する。**

```
対象: <基本名>
現行正本: v<X>.<Y>
  サイズ: <N>バイト
  SHA256: <先頭8桁>
  所在: <実パス>
  二拠点一致: あり / なし
旧版: v<...> は 旧版/ へ退避済み（<件数>件）
並走分岐: なし / あり（<詳細>）
未整理: <一時ファイル_月末整理 等に残置しているものがあれば列挙>
```

件数が1でない場合は「現行版は確定できません」と報告し、版上げには着手しない。AGENT_STATE.md に BLK として記録する。

## 禁止事項

- メモリ記載の版番号を根拠に断定すること
- `find -name` の使用
- 走査先の一部省略
- 件数アサーションを通さずに「確実に存在する」と述べること
